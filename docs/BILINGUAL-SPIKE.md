# 自動中英文混打：初步規格

使用者期望如晶晶輸入法般直接混打，不需切換模式。此文件是待實測的產品目標，不代表功能已完成，亦不依賴晶晶輸入法的程式碼或資料。

## 關鍵約束

標準注音的鍵位與英文字母重疊；部分短字串可以同時解釋為注音或英文。因此系統不可能根據所有前綴立即且無誤地判定。引擎需要保留可還原的原始按鍵，並在組字期間呈現及允許修正判斷；不能在尚有歧義時把文字永久上屏或丟棄按鍵。

## 驗證案例

`tests/fixtures/bilingual-cases.json` 記錄初步目標案例，標準鍵位、初始空組字、預設候選與英文詞表的前提須寫入後續測試 harness。例子目前只是期望值，並非通過測試的結果。應補齊無聲調單音節、英文與注音同鍵序、Backspace、Esc、游標、標點、URL、大小寫、焦點切換、候選字選取與多鍵位情境。

## 設計方向與待證明事項

- 保留未確定字串與游標，並行評估注音解析和英文詞典匹配；使用字詞頻率及上下文排序，非詞典英文字應可用明確方式確認原文。
- 空格既可能是注音一聲或字詞分隔符，不能單純把空格視為英文確認。大小寫、數字、符號及 URL 的邊界需逐項定義。
- 需要授權可驗證的英文詞庫；舊的第三方詞表不可使用。英文拼字匹配並不能保證專有名詞、自訂字及任意網址不受影響。
- 既有注音結果及候選流程必須能退回；使用者選擇、取消、切換視窗及撤銷不得遺失或重複文字。先用可重播測試和獨立原型驗證，再接入 IMK。
- 首版只針對標準注音配置探索，其他鍵位保留既有行為；實際延遲與準確率必須量測。

## 決策原型

`Sources/BilingualPrototype/Decision.swift` 是尚未接入輸入法的判斷原型：在明確邊界及只有一種解釋符合時提出建議；有歧義、前綴未完成或未知單字時回傳 undecided，呼叫端須保留原始按鍵。它不含正式詞庫、注音解析、上下文排序、IMK 按鍵流程或使用者介面，不能視為已支援混打。可用以下指令執行七個判斷案例：

```sh
swiftc Sources/BilingualPrototype/*.swift tests/bilingual_resolver.swift -o /tmp/zhuyin-bilingual-tests
/tmp/zhuyin-bilingual-tests
```

原型的 `CompositionBuffer.swift` 測試原始鍵序保留、退格和交付；它尚未處理 IMK 客戶端接受、游標、候選或焦點切換，不可接入正式輸入流程。

`EnglishLexicon.swift` 提供注入詞表後的大小寫不敏感單字及前綴查詢，測試資料僅為手寫範例。詞頻資源候選 [Wikipedia word frequency](https://github.com/IlyaSemenov/wikipedia-word-frequency) 的程式以 MIT 發布、語料取自維基百科；實際詞頻檔的來源、授權適用範圍及歸屬仍須確認，尚未匯入或用於產品。
