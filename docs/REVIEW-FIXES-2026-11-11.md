# 2026-11-11 review 修正

基準為 main `62ff443`；分支 `codex/fix-bilingual-recovery`。修正目的為避免中文組字被過早當作英文，以及讓使用者刪除誤判後能恢復中文。未更新已安裝的輸入法，跨 App 實機驗收仍待執行。

## 混打與恢復

- 新的中文上下文不再只因兩個字母命中英文詞就自動切英文；已有英文上下文時仍可直接接兩字母英文詞。
- 三字母以上自動辨識只使用前 20,000 個常用詞；可組成單一注音音節／前綴的鍵序先留在中文，包括 `sup`、`sul`、`ful` 及符號順序不同但仍可組成音節的 `url`。使用者仍可用 Tab 或 Shift 明確接受英文。這是有意採取的保守取捨，不代表所有中英歧義都已解決。
- 英文 run 保存整段文字（含數字、符號），刪空時結束這一段；明確選擇的 Caps Lock／Shift 英文模式不因刪空而取消。
- `reset()` 清除拼字修正、上一段英文上下文、聲調修正與 run 狀態；activation 同步 Caps Lock，deactivation 隱藏提示並清除暫態狀態。
- 混打與聲調修正只在標準注音、非傳統注音模式執行，其他配置沿用上游。無法在客戶端套用拼字替換時，Tab 回到上游處理。

## 記錄、儲存與還原

- 除錯記錄在第一次使用時清理過期內容，關閉記錄期間仍每小時維護；追加前檢查容量，保留最新的完整行且不超過 2 MB。單筆超過容量的記錄會被略過。記錄仍預設關閉，啟用 24 小時後停止。
- 詞典先成功寫入，再更新記憶體；新增／刪除失敗會拋出錯誤，UI 不再顯示虛假的成功訊息。此變更處理 JSON 詞典持久化；中文詞檔與 JSON 跨兩檔的原子交易仍未實作。
- 更新／還原來源及暫存副本均驗證 bundle ID、input-source ID、IMK connection 與兩個 input-mode ID；其他已簽章 App 不能作為 ZhuyinLM 備份還原。

## 驗證與限制

- `tests/bilingual_recovery.swift`：修正前 15 項斷言失敗；修正後涵蓋 5,000 組常用中文讀音的逐鍵路由、短詞歧義、刪空恢復、標點 run、Caps Lock 模式、跨 client 的拼字修正／英文上下文清除。
- `tests/storage_safety.swift`：確認超量記錄與停用時過期記錄的反例；驗證寫入失敗不回報成功、不變更記憶體狀態，以及容量限制與啟動清理。
- `tests/update_safety.py`：已簽章的其他 App／錯誤 connection 在任何備份及替換之前被拒絕；有效身分可在暫存目錄還原並留下備份。
- 以上新測試均已加入 `scripts/test.sh`。測試資料為手寫案例與已追蹤詞庫，沒有匯入使用者打字紀錄。
- 完整建置、簽章及身分檢查成功；`./scripts/test.sh` exit 0：130 個 XCTest、86 個 Swift Testing、既有五組 standalone 測試及新增 recovery／storage／update-safety 測試均通過；依原有腳本排除上游線上更新 API 測試。
- 自動路由重播不能代替實機 IMK 驗收；須實測 TextEdit、瀏覽器、其他 App、候選選取、焦點切換、Caps／Shift 以及許氏／倚天等配置。
- 詞庫採用最新 main 的既有資料；沒有修改詞表或將所有歧義詞直接刪除。較少見英文可能需要 Tab／Shift 確認。
